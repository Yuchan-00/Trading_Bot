# 에이전트 역할 구성안 (워크플로 종합 결과)

세 관점(risk-first / signal-quality-first / cost-and-simplicity-first)의 제안을 종합한 최종안. DESIGN.md에서 확정.

## 최종 역할표

| 역할 | 이름 | 모델 | 시점 | 스킬 | 목적 |
|---|---|---|---|---|---|
| `scanner` | 스캐너 (코드 전용 후보 선별·피처팩 빌더) | none | once per cycle (liquidity gates and packs every 15 min; candidate ranking refreshed hourly and reused in between) | `ccxt`, `multi-factor`, `sector-rotation`, `market-microstructure`, `execution-model`, `minute-analysis`, `technical-basic`, `ichimoku`, `candlestick`, `smc`, `volatility`, `perp-funding-basis`, `liquidation-heatmap`, `correlation-regime`, `correlation-analysis`, `risk-analysis`, `asset-allocation`, `sentiment-analysis` | Deterministic data + feature layer that runs before any LLM money is spent. Refreshes cached ccxt data for a ~30-50 symbol USDT universe, applies liquidity gates every cycle (min 24h quote volume, max spread bps, min top-5 depth, 15m volume >= 0.3x 20-bar mean, skip the minute around funding settlement 00/08/16 UTC), ranks candidates by cross-sectional z-scored factors (4h/1d momentum skipping the last 2-4 bars, 1h reversal, 24h realized vol, volume ratio, relative strength vs BTC, optional funding-z / OI-change) and re-ranks only hourly to stop churn; drops held / cooldown / revenge-blocked / NAME'd symbols and symbols up >15% in 24h without volume confirmation. Builds four compact JSON packs per symbol so no LLM ever sees raw candles: feature_pack (EMA/ADX vote, BB+RSI, OBV, Ichimoku triple-filter booleans on 15m+4h, candlestick composite, SMC BOS/ChoCH/FVG/OB zones, HV percentile, ATR%, VWAP distance, volume-vs-hour), flow_pack (annualized funding, 7d funding regime, OI 24h change, OI x funding matrix label, perp premium, long/short percentile, divergence flags, estimated liquidation clusters at 10x/20x/50x with cascade_risk, order-book OIR, data_confidence), risk_pack (hist VaR95/99 + CVaR95 on 1h/4h returns, kurtosis, corr to BTC and to each open position, beta, inverse-vol and CVaR-budget size suggestions, spread vs 24h median, taker depth vs planned notional, impact estimate, ATR noise check on the 2% stop), regime_pack (correlation edge density with causal smoothing, FUSED hysteresis 0.65 in / 0.45 out, first-mover verdict NAME/MACRO/AMBIGUOUS/ABSTAIN, BTC 4h regime label). Also computes the composite sentiment 0-100 (0.35 Fear&Greed cached 1h, 0.25 funding z, 0.20 long/short percentile, 0.20 decayed headline polarity) and the decayed event store. Only features on the validator's IC allowlist are included in prompts. |
| `technical` | 기술분석가 (가격구조 채널) | claude-haiku-5-5 | per symbol in (candidates ∪ open positions), deduplicated; 3 calls for 2 candidates + 1 position, run in parallel | `technical-basic`, `ichimoku`, `candlestick`, `smc`, `volatility`, `minute-analysis` | Evidence channel 1 (price structure only). Interprets the pre-computed multi-timeframe feature_pack for one symbol against a fixed rubric embedded in the prompt (trend / mean-reversion / volume vote; Ichimoku triple filter with 4h regime + 15m trigger; candlestick composite; SMC structure + FVG filter; HV-percentile bands) and returns a long / flat / avoid verdict, setup type, multi-timeframe agreement, a structural stop candidate (FVG/OB edge, Kijun or ATR) already clamped to the 2% cap, a target <= 4%, and a one-line falsifiable invalidation. It never sees news, funding or other agents' outputs and never computes indicators itself. For an open position it instead returns an exit_flag with reason (bearish strong signal, structure break, invalidation hit). Rule: prefer 'no setup' to a misread; -1 always maps to no-entry / exit-long (spot only). |
| `derivatives_flow` | 파생·자금흐름 분석가 (군집·청산 위험) | claude-haiku-5-5 | once per cycle, batched over all candidates + open positions | `perp-funding-basis`, `crypto-derivatives`, `liquidation-heatmap`, `investor-lenses`, `market-microstructure` | Evidence channel 2, independent of price structure, and the bot's only on-chain proxy. ONE batched call per cycle over all candidates and open positions reads the code-labelled flow_pack (funding regime, OI x funding matrix, perp premium, long/short percentile, divergence flags, estimated liquidation clusters and cascade_risk, OIR) and places each symbol on the euphoria..capitulation pendulum. Its job is mostly negative: flag crowded longs (overheated_long, leveraged_long_buildup), a dense long-liquidation cluster within 2% below price (the stop would sit inside the cascade), squeeze direction and cascade risk. The one bullish setup it may raise is washout_setup (contrarian long after a flush with funding reset), which lets a candidate into the debate even when the technical read is flat. Liquidation clusters are projected, not observed, so the call must carry data_confidence and the consumers treat low-confidence flags as block/shrink-only, never as approval. |
| `news_sentiment` | 뉴스·이벤트 감성 분석가 | claude-haiku-5-5 | once per cycle, only if new headlines exist (otherwise 0 calls; the decayed event store is reused) | `event-driven`, `sentiment-analysis`, `research-discipline` | Evidence channel 3. Scores only NEW, deduplicated RSS headlines (hash + (symbol, event_type, 1h bucket) dedup, title-only, <= 40 per call) on the fixed 7-step -1.0..+1.0 event scale with event_type, affected symbols, a <=20-word summary and a stale flag (>24h not intraday-actionable, >7d stale), and raises a hard risk_event flag for hack / exploit / delisting / regulatory action / exchange incident / stablecoin depeg / ETF decision on a watchlist or held symbol. Everything numeric happens in code afterwards: per-event-type hourly decay (sentiment ~6-12h half-life, regulatory slower), /score/ < 0.2 dropped, per-symbol and market event_signal, and the 0.20 headline-polarity component of the composite sentiment score. The LLM never sets the composite number. Must report feed_health: an empty feed is not a calm market. The call is skipped entirely when no new headlines arrived; decay still runs in code. |
| `bull` | 강세 변론가 | claude-sonnet-5-5 | per candidate that passed the post-analyst code gate G1 (in parallel with bear) | `behavioral-finance`, `research-discipline`, `event-driven` | Builds the strongest honest case for a long entry (or for keeping a long) on one candidate from the frozen evidence packs (technical, derivatives_flow, news_sentiment outputs plus the scanner factor row and composite sentiment), using the underreaction / fear-side checklist: momentum on the 1h-4h horizon with volume confirmation, RSI(5) extreme rebound, capital-gain overhang (price vs 60-bar VWAP) < -0.3 easing selling pressure, extreme-fear or deeply negative funding as contrarian support, washout_setup from flow, catalysts from the event store. Every thesis point must cite a pack field ('because <data> -> therefore <judgment>'). It is forced to produce >= 2 disconfirming data points from the same packs, name the main risk to its own case and an observable trigger that would disprove it, and give an expected horizon in 15m bars. It never sees the bear's output and runs only after the code pre-gate confirmed a long-side setup with no hard blocks, so Sonnet is never spent on dead candidates. |
| `bear` | 약세 변론가 (반대심문·사전부검) | claude-sonnet-5-5 | per candidate that passed G1, in parallel with bull | `investor-lenses`, `behavioral-finance`, `research-discipline`, `correlation-regime`, `perp-funding-basis` | Independent adversary with a different procedure from the bull, not a mirror image: a Munger-style inversion rewritten for a 15m spot long. Enumerates >= 3 death paths from different families (liquidation cascade / liquidity vacuum, news or exchange shock, regime flip or BTC beta shock, crowded-positioning unwind, data incident), each with an observable trigger from our data, a probability band (unknown is not low) and time-to-impact in bars; applies the overreaction / greed checklist (abnormal volume > 3x halves the momentum horizon, CGO > 0.2 disposition selling, funding > +0.05%/8h euphoria, price new highs with falling funding, RSI/BB overbought, composite sentiment > 80, chasing a > 15% 24h spike without volume); must produce the disconfirming data point for every positive in the packs and state what would disprove the bear case. Verdict survivable / survivable_if_monitored / decline. A 'decline' verdict is a code-enforced kill (G2) that drops the candidate before risk_manager and head are called; its strongest point is quoted verbatim by the head and in the Telegram BUY message. Never sees the bull's output. |
| `risk_manager` | 리스크 관리자 (거부권 보유) | claude-sonnet-5-5 | once per cycle, batched; runs whenever at least one candidate survived G2 or an open position exists | `risk-analysis`, `correlation-regime`, `correlation-analysis`, `asset-allocation`, `market-microstructure`, `execution-model`, `thesis-tracker`, `trade-journal`, `strategy-dev-manager`, `shadow-account`, `volatility`, `behavioral-finance` | Evidence channel 4 and the pre-decision gatekeeper with a binding veto the head cannot override (it may only shrink further). ONE batched call per cycle over every surviving candidate and every open position. Reads only code-computed numbers (risk_pack, regime_pack, liquidity, account state, journal bias severities, strategy decay state) plus the bull/bear/analyst outputs and returns, per candidate, approve / conditional / veto with max size inside the caps (inverse-vol and CVaR-budget scaled, halved when FUSED), stop <= 2% and TP <= 4%, a net R:R estimate after 0.30% round-trip cost, required monitoring conditions, and a 1-5 reliability score for each bull point against the bear's death paths. Per open position it re-scores the stored thesis with health = 10 - 3*broken - 2*impaired - 1*weakening - 5*red_lines (assumption statuses pre-checked in code, clamped 1..10) and recommends hold / trim / exit. Globally it sets this cycle's confidence floor (0.65; 0.75 when FUSED, decay_state warning/decayed, or chasing/overtrading severity high) and may pause entries. Several of its rules are duplicated as hard code gates (G3) so a lenient model cannot leak a bad trade; the LLM adds the judgement layer (which conditional entries are acceptable, how much to shrink, impaired vs broken). |
| `head` | 총괄 결정자 | claude-opus-5-5 | once per cycle, only when at least one candidate is approved/conditional or an open position is flagged for a SELL decision; skipped during halts and when nothing is actionable | `investor-lenses`, `behavioral-finance`, `thesis-tracker`, `sentiment-analysis`, `event-driven`, `research-discipline` | Final BUY / SELL / HOLD per symbol with confidence and a falsifiable thesis, in ONE batched call per cycle, made only for candidates the risk manager approved or marked conditional and for open positions flagged by risk (trim/exit or health <= 6) or by a technical exit_flag; otherwise code emits HOLD and Opus is not called. Applies the stacking protocol: read bull and bear independently, classify every disagreement (horizon / caliber / risk_preference / information), never average confidences, quote the losing side's strongest point verbatim. Prompt rules: no BUY on a risk veto (code enforces it anyway); no BUY on any symbol with risk_event; no BUY without 4h price above the Ichimoku cloud unless derivatives_flow.washout_setup is true and the bear verdict is survivable; never act on sentiment alone; confidence may not exceed min(bull.confidence, risk.confidence) + 0.05. Must answer the debiasing questions as required JSON fields. On every BUY it emits a thesis: 2-3 one-line reasons, 2-4 falsifiable assumptions in market terms (e.g. 'price holds above 4h EMA26', 'funding stays < 0.05%/8h', 'no risk_event headline on symbol'), red lines beyond the hard SL, horizon in bars and a reevaluation trigger; the thesis is stored with the position and re-scored by risk_manager every cycle. Default is HOLD; it is told which channels abstained due to timeout/schema failure. |
| `journal` | 매매일지·사후분석 기록자 | claude-haiku-5-5 | post-trade (one call per closed trade) + once per day at 00:05 UTC; never per cycle | `trade-journal`, `performance-attribution`, `report-generate`, `shadow-account`, `strategy-dev-manager`, `strategy-generate` | Post-trade and daily narrator; never inside the 15-minute decision loop. Code computes every number first: FIFO P&L after fees, hit rate, avg win/loss, profit factor, Sharpe/Sortino/Calmar/MDD vs BTC buy-and-hold, per-symbol / per-channel / per-setup contribution, the four behavioral-bias severities (disposition >= 1.2/1.5, overtrading, chasing after +3% run-up, anchoring), the five-bucket shadow attribution (noise trades, early exits, late exits, overtrading, missed signals), gate statistics (bear-decline rate, risk-veto rate, G1-G4 rejection counts, counterfactual outcome of declined candidates), LLM call counts/cost, and the rolling strategy decay state (healthy/warning/decayed/disabled over the last 60 closed trades with min-sample rules). Haiku then (a) per closed trade writes a 3-5 bullet post-mortem, marks which thesis assumptions held or broke, tags the trade from a fixed enum and produces the Telegram text; (b) once per day writes the review in the fixed schema with >= 3 risks and >= 2 'Change X from A to B' action items, or abstains until >= 20 closed trades. It is forbidden from citing any number not in the computed table. Bias severities and decay state feed back into next cycle's risk_manager inputs. |
| `validator` | 검증기 (오프라인 백테스트·승격 게이트) | none | on demand / nightly, never inside the 15-min cycle | `backtest-diagnose`, `strategy-generate`, `factor-research`, `quant-statistics`, `ml-strategy`, `minute-analysis`, `execution-model` | Offline, code-only replay harness and promotion gate; never inside the 15-minute cycle. Minimal vectorized 15m backtester with 'hold' semantics (enter on signal, exit on SL/TP/flip), 10 bps commission plus the slippage table (BTC/ETH 5 bps, alts 15-30, sqrt impact above 5% participation), delay_bars = 1, warm-up exclusion, annualization 365 x bars/day. Enforces the five hard gates (metrics/equity/trades non-empty, exit 0, no NaN equity, trade_count > 0), the bug checks (zero trades, > N cycles without a signal, capital utilization < 50%, open position at end), separation of API errors from logic errors, max 3 repair iterations. Runs the Spearman rank-IC check (/IC/ > 0.03, IR > 0.5, IC > 0 share > 55%, factor-at-t / return-after-t) on every scanner factor and feature the prompts cite and maintains the feature allowlist; runs bootstrap Sharpe significance and walk-forward before any config change is promoted paper -> testnet -> live; runs the mock-backend data-validation checklist (required OHLCV columns, >= 300 rows, NaN ratio <= 20%). Also compares paper results against a rules-only baseline so over-conservatism (zero-trade failure) is visible. |

### 역할별 입력/출력

#### `scanner` (스캐너 (코드 전용 후보 선별·피처팩 빌더))
- 입력: OHLCV 15m/1h/4h/1d for the watchlist (ccxt, cached per cycle, paginated by since), 24h tickers (quote volume, spread), order book top-20 snapshot, Binance futures public: funding (current + 7d), open interest, long/short ratio; forced-order stream optional, alternative.me Fear & Greed (cached 1h, canned in mock), Decayed event store written by news_sentiment, Bot state: open positions, cooldowns, revenge blocks, halt flags, previous hourly ranking, Static sector tag map and validator feature allowlist from config
- 출력 필드: candidates[] {symbol, composite_z, factor_table{momentum_4h, momentum_1d, reversal_1h, rv_24h, volume_ratio, rs_vs_btc, funding_z, oi_change_24h}, sector_tag}, feature_pack{symbol} (technical labels per tf: ema_state, adx, rsi14, rsi5, bb_position, obv_trend, vote, mtf_agreement, ichimoku{tk_cross, price_vs_cloud, cloud_bullish, cross_strength}, candle{patterns[], score}, smc{bos, choch, fvg_dir, nearest_zone_low, nearest_zone_high}, hv_pct, atr_pct_1h, vwap_distance_pct, volume_vs_hour_avg, cgo_60, abnormal_volume_multiple), flow_pack{symbol} (funding_8h, funding_annualized, funding_regime, oi_change_24h_pct, oi_funding_label, perp_premium_pct, ls_ratio_pctile, divergence_flags[], est_liq_clusters[], nearest_long_liq_below_pct, cascade_risk, liq_24h_total|null, oir_top5, data_confidence), risk_pack{symbol} (var95_1h, var99_1h, cvar95_1h, rv_20, rv_60, hv_pct, kurtosis, corr_to_btc, corr_to_open_positions{}, beta_btc, inverse_vol_size_pct, cvar_size_pct, spread_bps, spread_vs_24h_median, depth_taker_usdt, impact_bps_est, stop_vs_atr_noise_ok), regime_pack {fused, density, verdict, named_symbols[], btc_regime_4h}, liquidity{symbol} {spread_bps, depth_top5_usdt, depth_top20_usdt, amihud_1h, est_impact_bps_for_planned_order}, composite_sentiment_0_100 and its components; event_signal per symbol with top-3 decayed event summaries, skipped[] {symbol, reason}, universe_size, ranked_at, feature_pack_version, data_quality_ok
- 모델 선택 이유: All three proposals agree: everything here is pandas arithmetic that must be reproducible and unit-testable against synthetic candles. An LLM scanner would only restate z-scores, add cost and insert a non-reproducible step before any evidence exists.

#### `technical` (기술분석가 (가격구조 채널))
- 입력: feature_pack for the symbol (15m/1h/4h labels only, plus last 20 closes of 1h as a compact array), Decision rubric and the 2%/4% caps stated in the system prompt, For open positions: entry price, current SL/TP, unrealized %, bars held, stored invalidation
- 출력 필드: symbol, direction (long|flat|avoid), setup_type (trend_continuation|mean_reversion|breakout|none), timing (now|wait_pullback|wait_confirmation), mtf_agreement (bool), score (-5..+5), confidence (0-1), stop_candidate_price and stop_pct (<=2), sl_reference (zone|kijun|atr), target_candidate_price and tp_pct (<=4), invalidation (one line, in market terms), noise_check (bool: 2% stop sits outside normal ATR noise), exit_flag (bool) + exit_reason (open positions only), evidence[] (<=3, each naming a feature_pack field)
- 모델 선택 이유: P1 and P2 agree: the hard part (indicator math) is done in code; the LLM only maps a small labelled JSON to a direction and a level. Haiku is accurate enough for rubric-following and makes it affordable to re-read open positions every cycle, which is where losses are cut early.

#### `derivatives_flow` (파생·자금흐름 분석가 (군집·청산 위험))
- 입력: flow_pack per symbol (funding_now, funding_7d[], funding_annualized, funding_regime, oi_change_24h, oi_funding_label, perp_premium_pct, ls_ratio_pctile, est_liq_clusters[], nearest_long_liq_below_pct, cascade_risk, liq_24h_total|null, oir_top5/top20, spread_bps, divergence_flags[], data_quality), Threshold table in the system prompt (funding > +0.05%/8h extreme long crowding; < -0.02%/8h squeeze territory; OI +5% with funding > +0.03% = leveraged_long_buildup; cluster gap < 2% = high cascade risk)
- 출력 필드: per_symbol[] {symbol, posture (capitulation|fear|neutral|greed|euphoria), regime, crowding_risk (low|moderate|high), squeeze_direction (up|down|none), cascade_risk (low|moderate|high), nearest_long_liq_cluster_pct_below, stop_inside_cascade (bool), washout_setup (bool), block_new_longs (bool), block_reason, flow_bias (long|neutral|avoid), confidence (0-1), evidence[] citing field names}, market_wide_note (one line), data_confidence (high|low)
- 모델 선택 이유: P1 and P2 both keep it separate from technical and batch it: regime labels and liquidation maths are pre-computed, so the call is a labelled-table interpretation Haiku handles, and batching keeps this channel at ~1 call regardless of candidate count. Its binary block flags are consumed by code gates, not by expensive debate.

#### `news_sentiment` (뉴스·이벤트 감성 분석가)
- 입력: headlines[] {id, ts, source, source_grade, title} new since last cycle, max ~40, Watchlist symbols and alias map (Bitcoin -> BTC, Ethereum -> ETH ...), Current time and the 24h / 7d staleness rule, feed_health {items_fetched, oldest_ts, newest_ts, errors}, Previous cycle's unexpired events (so they are not rescored)
- 출력 필드: events[] {headline_id, score (-1..1 on the 7-step scale), event_type (hack|regulatory|listing|delisting|macro|etf|exchange|protocol|sentiment|technical_break|other), symbols[], summary (<=20 words), stale (bool)}, risk_event (bool), risk_event_symbols[], market_tone (-1..1) + one-sentence note, feed_health_note
- 모델 선택 이유: Unanimous: headline labelling on a fixed scale is a Haiku-grade classification task; batching and skip-on-no-news make the average cost well under one call per cycle. The risk_event flag is its only output with trading power and it only ever removes trades.

#### `bull` (강세 변론가)
- 입력: technical output for the symbol + feature_pack extract (cgo_60, rsi5_1h, abnormal_volume_multiple), derivatives_flow per_symbol entry, news_sentiment events for the symbol, market_tone, composite_sentiment_0_100 and decayed event_signal, scanner factor row and liquidity block, regime_pack summary (btc_regime_4h, fused), Open position state for the symbol if any (entry, unrealized %, stored thesis)
- 출력 필드: symbol, case_strength (1-5), thesis_points[] (<=3, each {claim, evidence_field}), catalysts[], underreaction_evidence (momentum horizon, volume confirmation, cgo_60), entry_trigger (one line), expected_horizon_bars, invalidation_level, disconfirming_evidence[] (>=2, mandatory, from the packs), main_risk_to_bull_case, what_would_disprove (observable trigger), confidence (0-1)
- 모델 선택 이유: All three agree on Sonnet: argument construction with mandatory self-refutation needs a stronger reasoner than Haiku (which tends to produce one-sided cheerleading), but it is not the final decision, so Opus is unnecessary.

#### `bear` (약세 변론가 (반대심문·사전부검))
- 입력: Same frozen evidence packs as bull (technical, derivatives_flow, news_sentiment, scanner row, cgo_60, rsi5, abnormal_volume_multiple, composite sentiment), regime_pack {fused, density, verdict, named_symbols[], btc_regime_4h}, corr_to_btc_1h, hv_pct, Open positions and this candidate's correlation to each of them
- 출력 필드: symbol, death_paths[] (>=3) {family, description, observable_trigger, probability_band (low|mid|high|unknown), time_to_impact_bars}, greed_flags[] / overreaction_evidence, disconfirming_evidence[] (>=1, one per bull-style positive in the packs), strongest_point (one line, quoted verbatim by the head when the bear loses), what_would_disprove_bear (one line), verdict (survivable|survivable_if_monitored|decline), monitoring_conditions[] (if survivable_if_monitored), confidence (0-1)
- 모델 선택 이유: Unanimous Sonnet: adversarial reasoning with multiple failure families and explicit triggers is the single highest-leverage LLM task for avoiding bad entries; a Haiku bear produces generic risks that restate the technical read, and every 'decline' that fires saves the downstream Sonnet/Opus calls.

#### `risk_manager` (리스크 관리자 (거부권 보유))
- 입력: Per candidate: technical, derivatives_flow, bull, bear outputs (verdicts and strongest points), risk_pack per symbol (VaR95/99, CVaR95, rv, hv_pct, kurtosis, corr_to_btc, corr_to_open_positions{}, beta, inverse_vol_size_pct, cvar_size_pct, spread_bps vs 24h median, depth_taker_usdt, impact_bps_est, stop_vs_atr_noise_ok, order_notional_vs_15m_volume_share), regime_pack {fused, density, verdict, named_symbols[], btc_regime_4h}, account_pack {equity, daily_pnl_pct, drawdown_pct, drawdown_ladder_level, exposure_pct, position_count, consecutive_losses, cooldowns, decay_state (healthy|warning|decayed|disabled), bias_severities{disposition, overtrading, chasing, anchoring}, noise_trade_share}, news risk_event symbols and derivatives block flags, open_positions[] {symbol, entry, unrealized_pct, bars_held, thesis{assumptions[], red_lines[]}, code-evaluated assumption_status[], red_line_hits[], technical exit_flag}
- 출력 필드: candidates[] {symbol, verdict (approve|conditional|veto), veto_reasons[], conditions[], max_size_pct (<=10, halved if fused), stop_pct (<=2), take_profit_pct (<=4), rr_net_estimate, bull_point_reliability[] {point, score_1_5, pushback}, required_monitoring[], correlation_note}, positions[] {symbol, assumption_status[] (holding|weakening|impaired|broken), red_lines_triggered[], health (1-10), action (hold|trim|exit), reason}, global {entries_paused (bool), pause_reason, confidence_floor (>=0.65), exposure_cap_pct, portfolio_note}, risk_note (<=2 sentences for Telegram/journal), confidence (0-1)
- 모델 선택 이유: Unanimous: the veto is the most consequential LLM output and must weigh a dozen numeric packs against two arguments with numerically consistent sizes and levels; too consequential for Haiku, but every number is pre-computed and the rules are explicit, so Opus adds nothing. One batched call gives the portfolio-level view (correlation, exposure) at fixed cost.

#### `head` (총괄 결정자)
- 입력: Per approved/conditional candidate: scanner row, technical, derivatives_flow, news_sentiment (symbol + market), bull, bear, risk_manager verdict and constraints (max_size_pct, stop_pct, take_profit_pct, confidence_floor), Per flagged open position: stored thesis + health, technical re-read / exit_flag, risk recommendation, P&L, bars held, regime_pack, account_pack, composite_sentiment, event_signal + suggested combined score (0.6 tech / 0.4 event) as information only, Vetoed / declined candidates listed as context with reasons (not actionable), Hard limits restated verbatim (10%/symbol, 3 positions, 30% exposure, SL<=2%, TP<=4%, conf >= floor) and the list of abstained channels
- 출력 필드: decisions[] {symbol, action (BUY|SELL|HOLD), confidence (0-1), size_pct (<= risk max), stop_pct (<=2), tp_pct (<=4), thesis{reasons[] (2-3), assumptions[] (2-4 falsifiable), red_lines[], horizon_bars}, disagreement_class (horizon|caliber|risk_preference|information|none), losing_side_strongest_point (verbatim), decisive_factor, rationale (<=60 words)}, debias {anchored_to_entry, ignored_bearish_news, overtrading, chasing_spike, acting_on_sentiment_alone} (all bool), reevaluation_triggers[], hold_reasons[] for every non-trade, cycle_note (one line for Telegram/dashboard)
- 모델 선택 이유: Unanimous and user-mandated: this is the only call that must integrate four heterogeneous evidence channels, reason about disagreement instead of voting, and commit to a thesis that will be audited every cycle. Batching all symbols into one call keeps Opus at <= 1 call per cycle and gives it the whole-portfolio view the position cap and correlation rule require.

#### `journal` (매매일지·사후분석 기록자)
- 입력: Closed trade record {symbol, side, entry, exit, qty, fees, pnl_pct, bars_held, exit_reason (SL|TP|time_stop|head_SELL|risk_exit|kill|regime_alarm), thesis snapshot, cycle-by-cycle thesis health history, bull/bear verdicts, channel agreement flags, risk notes}, Daily metrics table computed in code (returns, benchmark BTC, bias severities, attribution buckets, gate statistics, decay state, LLM call counts and cost), Count of closed trades to date
- 출력 필드: post_trade {trade_id, summary_bullets[] (3-5), assumptions_at_exit[] {assumption, status}, broken_assumption, near_miss_rules[], lesson (<=2 sentences), lesson_tag (fixed enum: thesis_broken|stop_too_tight|chased_spike|news_ignored|good_exit|time_stop|regime_exit|...), telegram_text (<=400 chars)}, daily_review {summary_bullets[] (3-5), what_worked[], what_failed[] (each with a number from the table), risks[] (>=3), action_items[] {param, from, to, reason} (>=2) or abstain_reason, do_not_change_yet (bool), telegram_text}
- 모델 선택 이유: Unanimous: narrating pre-computed tables is a cheap task, and Haiku keeps the per-trade note effectively free so it can run on every trade event as the user asked. The daily review can be switched to Sonnet by config if prose quality matters.

#### `validator` (검증기 (오프라인 백테스트·승격 게이트))
- 입력: Cached candles or mock backend data, Proposed config diff and prompt version, Bot journal (closed trades, decision logs) for decay/health state and gate statistics
- 출력 필드: gates_passed (bool), metrics {sharpe, sortino, calmar, max_dd, win_rate, profit_factor, trade_count, capital_utilization, cost_sensitivity_bps_table}, bootstrap_sharpe_ci, ic_report per feature {ic_mean, ic_std, ir, pos_share, allowed_to_cite (bool)}, bug_flags[], baseline_comparison (rules-only vs LLM pipeline), promotion_allowed (paper|testnet|live)
- 모델 선택 이유: P1 and P3 both name it as a code role and P2 insists it stay out of the live loop: pure statistics, where an LLM would only fabricate metrics. Its outputs (feature allowlist, decay state, promotion verdict) constrain what the LLM roles may rely on and when live mode may be entered.

## 사이클 흐름

Cycle = every 15 minutes, T+5s after the candle close. Layers run with a thread pool; per-call timeouts Haiku 20s / Sonnet 40s / Opus 60s, one retry max, any failed or schema-invalid output becomes an explicit 'abstain' value that the head is told about; hard cycle deadline 5 minutes after which the cycle is HOLD-all with a Telegram warning. Code SL/TP/time-stop checks on open positions run first every cycle and never wait on an LLM. G = code gate, 0 LLM calls.

G0 Pre-flight (code): kill switch / STOP / STOP_ALL, daily -3% halt, 3-consecutive-loss halt, drawdown ladder level (-6% auto-STOP), LLM-pause state after repeated API errors, daily LLM spend cap, bot.lock, data-quality check (stale bars, NaN, outliers -> skip symbol or cycle), funding-settlement minute (00/08/16 UTC +-1 min -> no new orders). If any account-level halt is active: only code-managed SL/TP/time-stop (96 cycles) on open positions, Telegram on any exit, cycle ends with 0 LLM calls.

Step 1 scanner (code): refresh cached data; liquidity gates every cycle; hourly re-rank (reused in between); drop held / cooldown (4 cycles) / revenge-blocked (8 cycles after a loss) / NAME'd symbols and > 15% 24h spikes without volume; build feature_pack, flow_pack, risk_pack, regime_pack, composite sentiment and decayed event store. Regime gate: MACRO or NAME alarm -> candidate list emptied, stops tightened by code, NAME'd held symbol flagged for exit review; FUSED -> max size halved and confidence floor 0.75 for the whole cycle. Regime transitions are logged and sent to Telegram. Output: up to 3 candidates (default 2).

Step 2 independent analysts (Haiku, parallel, strictly partitioned): technical per symbol in candidates ∪ open positions; derivatives_flow once, batched; news_sentiment once only if new headlines exist. None sees another's output. Code then updates the event store and composite sentiment and marks risk_event symbols.

G1 Candidate pre-gate (code): a candidate proceeds only if (technical.direction == long AND mtf_agreement AND technical.confidence >= 0.55 AND noise_check true) OR (derivatives_flow.washout_setup AND technical.direction != avoid); dropped if derivatives_flow.block_new_longs, stop_inside_cascade, or cascade_risk == high with the nearest long-liq cluster within 2% below; dropped if news risk_event hits the symbol; dropped if composite sentiment > 80 unless setup_type == mean_reversion with washout_setup; dropped if position_count == 3 or exposure cap reached or |corr| > 0.8 to an open position. Everything dropped is HOLD at zero further cost. If no candidate survives AND no open position has an exit_flag or health concern -> HOLD emitted by code, cycle ends (Sonnet/Opus never spent).

Step 3 debate (Sonnet, parallel, independent): bull and bear per surviving candidate on the same frozen evidence; neither sees the other.

G2 Bear kill (code): bear.verdict == decline -> candidate dropped and logged with death_paths (decline rate and counterfactual outcome tracked by the journal); survivable_if_monitored carries monitoring_conditions forward.

Step 4 risk_manager (Sonnet, 1 batched call, runs if any candidate survived G2 or any position is open): approve / conditional / veto with max_size_pct, stop_pct, take_profit_pct, rr_net_estimate and bull_point_reliability per candidate; health + hold/trim/exit per position; global confidence_floor and entries_paused.

G3 Risk veto gate (code, duplicated so a lenient LLM cannot leak a trade): vetoed candidates dropped (shown to the head only as context); FUSED -> size halved, floor 0.75; decay_state decayed or chasing/overtrading high -> floor 0.75 or entries paused; order notional > 5% of (24h volume / 96) -> shrink or block; spread > N x 24h median or taker depth < k x notional -> block; expected slippage + 2x fee > 25% of stop distance -> block; CVaR95 x size would breach the 2% stop or the daily -3% budget -> size = min(10%, risk_budget / CVaR95). If nothing is approved/conditional and all positions are 'hold' with no exit_flag -> HOLD, no head call.

Step 5 head (Opus, 1 batched call): BUY/SELL/HOLD per actionable symbol with confidence, thesis (assumptions + red lines), disagreement class, losing side's strongest point, debias fields, reevaluation triggers.

G4 Decision validation gate (code, executor): reject -> HOLD and log the gate name for any BUY with confidence < max(0.65, confidence_floor), size_pct > min(head, risk max, inverse-vol, CVaR size, 10%), total exposure > 30%, stop_pct > 2%, tp_pct > 4%, net R:R after 0.30% round-trip cost < 1.5 (stop tightened only, never TP widened; if the tightened stop falls inside ATR noise the trade is skipped), debias chasing_spike or acting_on_sentiment_alone true, missing/empty assumptions, cooldown or revenge block active, max 3 positions, no averaging down, JSON schema failure or timeout (never retry into an order). Head SELL on an open position needs confidence >= 0.65; a risk 'exit' executes only on a broken red line or health <= 4 for two consecutive cycles; code SL/TP/time-stop execute regardless.

Step 6 execution (code): spot market order; paper fill = last +- fixed bps by liquidity tier (BTC/ETH 5, alts 15-30) or sqrt impact, fill at next bar open (delay_bars = 1); testnet via ccxt sandbox; live only with MODE=live + CONFIRM_LIVE=YES + console confirmation. After fill: SL/TP re-anchored to the actual fill (SL <= 2%, TP <= 4%), state saved atomically, thesis stored with the position, Telegram trade message sent (queued with retry; state is persisted before notification).

Step 7 post-trade (Haiku, event-driven): journal per closed trade (Telegram text included); daily at 00:05 UTC code computes metrics, bias severities, attribution, gate statistics and decay state, journal writes the daily review (Telegram + dashboard); severities and decay state are refreshed for next cycle's risk_manager. Validator runs offline/nightly only and gates any config or mode promotion. Everything is reproducible with a mock backend (canned candles, order books, futures data, RSS items with fixed timestamps, deterministic fills, mock LLM backend returning schema-valid fixtures per role).

## 호출 횟수 추정
With 2 candidates and 1 open position, worst case (both candidates survive every gate, new headlines present, a decision is needed): technical 3 (Haiku: 2 candidates + 1 position) + derivatives_flow 1 (Haiku, batched) + news_sentiment 1 (Haiku) + bull 2 + bear 2 (Sonnet) + risk_manager 1 (Sonnet) + head 1 (Opus) = 11 calls (5 Haiku, 5 Sonnet, 1 Opus), i.e. ~5.5 per candidate symbol, under the 14-call ceiling. Typical cycle (one candidate dropped at G1, often no new headlines): 7-8 calls (4 Haiku, 2-3 Sonnet, 0-1 Opus). No setup at all with one open position: 4-5 Haiku + 1 Sonnet (risk_manager position review), 0 Opus unless the position is flagged. Halted or data-quality-skipped cycles: 0 calls. Journal adds 1 Haiku per closed trade + 1 per day; validator adds 0 LLM calls. Rough daily volume at 96 cycles: ~350-500 Haiku, ~100-300 Sonnet, ~10-60 Opus depending on how often G1/G2/G3 pass; prompt-cached static system prompts and compact JSON packs (<2k input tokens per analyst, <6k for risk, <8k for head) keep token volume low. A config knob can batch bull/bear into one call each (P3 style) and a daily spend cap degrades the bot to HOLD-only when exceeded. Check current API pricing rather than estimating USD from memory.

- Open-position thesis health drop to <= 4 or red line triggered: trim/exit recommendation and what the head decided

- Operational: bot start/stop/crash, mode change (paper -> testnet -> live confirmation), LLM backend failure or pause after repeated timeouts and resumption, cycle deadline exceeded (HOLD-all), data-quality skip streak (>= 3 consecutive cycles), state file corruption or lock conflict detected
- Heartbeat (configurable, default every 4 hours) with open positions, exposure and daily P&L so silence is distinguishable from a crash

## 제외한 스킬과 이유

- chanlun - unanimous: needs the czsc dependency or a sizeable fractal/stroke/pivot implementation, noisy on 15m-4h crypto bars, duplicates SMC BOS/ChoCH structure; may return behind a feature flag if the validator shows IC > 0.03
- elliott-wave - majority (P1, P3): subjective wave counts on intraday crypto, the reference engine's day-based min-bars bug, and a false 'ABC complete' long is exactly the bad trade the gates exist to prevent; P2's feature-flag option deferred until the validator's IC gate passes
- harmonic - majority (P1, P3): XABCD patterns are rare on 1h/4h and the implied stop usually exceeds the 2% cap, so most detections are unusable; SMC zones already supply stop references
- okx-market - unanimous: OKX endpoint catalog, bot is Binance-only via ccxt; only its field checklist informs the data adapter spec
- ml-strategy - unanimous as a signal: walk-forward sklearn model is unproven black-box infrastructure the bear and risk manager cannot interrogate; only its data-validation checklist and leakage rules are reused inside the validator
- crypto-derivatives (options, term structure, carry/calendar sections) - Deribit IV/skew, dated futures and leverage parameters we do not have or trade; only the funding-rate table and the extreme-funding-is-contrarian rule survive inside derivatives_flow
- sentiment-analysis (PCR, margin balance, northbound flows, social scraping, position-size mapping) - no free source; replaced by the code-computed Fear&Greed + funding z + long/short percentile + headline polarity composite used only as a confidence modifier
- asset-allocation (MPT, Black-Litterman, all-weather, config.json optimizers, rebalancing) - meaningless with max 3 spot positions; only inverse-vol sizing within the 10% cap and the correlation > 0.8 'one position' rule are kept as code
- correlation-analysis (cointegration, Johansen, Kalman, lead-lag, pairs signals) - long-only spot bot cannot trade spreads; only rolling correlation/beta and BTC regime labels are kept as risk_pack code
- risk-analysis (Monte Carlo GBM, EVT/GPD, equity stress table) inside the cycle - too slow and noisy on 15m data; kept only for the nightly validator/journal report with crypto flash-crash shocks
- performance-attribution (Brinson-Fachler, Carino, Fama-French, timing tests) - no sectors or factor returns for a 3-position crypto book; only Sharpe/Sortino/Calmar/MDD vs BTC buy-and-hold and per-channel contribution are computed for the journal
- investor-lenses (10 of the 12 lenses) - fundamental equity procedures with no inputs here; only Munger inversion (bear), the stacking/disagreement protocol (head) and the Marks pendulum (derivatives_flow) are used, with no investor names in prompts
- shadow-account (user journal upload, PDF report, multi-market backtest) - replaced by the five-bucket attribution over the bot's own journal, code only
- market-microstructure (VPIN, Kyle lambda, TWAP/VWAP/IS execution, A-share auction rules) - VPIN needs fetch_trades wiring and the bot only sends small market orders; spread/depth/OIR/Amihud/impact are kept as code inputs
- sector-rotation (Shenwan taxonomy, earnings/PMI/policy scores, supply-chain transmission) - A-share only; only the momentum-skip-recent-bars ranker formula, static sector tags and the 'do not chase a > 15% spike' rule are reused in the code scanner
- strategy-dev-manager (paper ingestion, OCR, SDM tools, SignalEngine contract) - only the decay thresholds and state machine survive as a code-computed health state read by risk_manager
- backtest-diagnose / factor-research / quant-statistics / strategy-generate as LLM roles - valuable but kept strictly as offline code inside the validator so nobody adds a 'backtest agent' call to the live cycle
- An LLM scanner role (from multi-factor / sector-rotation) - would only restate z-scores the code already ranked, costing a call and adding a non-reproducible step before evidence exists
- Separate pattern-school agents (candlestick, ichimoku, smc, elliott, harmonic as their own calls) - they all read the same candles and would herd; merged into one feature pack read by one Haiku technical call
- A merged market_analyst role (P3) - rejected in favour of partitioned technical + derivatives_flow so the head receives genuinely independent evidence channels; derivatives_flow is batched so the extra cost is one Haiku call
- A separate executor_gate role (P3) - its hard limits are kept in full but as code gates G0-G4 and the execution step inside the cycle flow, not as a roster entry, to stay within 10 roles

## 위험과 완화

- Over-conservatism / zero-trade failure: stacked gates (G1 pre-gate, bear kill, binding risk veto, 0.65/0.75 floors) can starve the bot. Mitigation: journal tracks per-gate rejection rates, bear-decline and risk-veto rates and the counterfactual outcome of declined candidates on the dashboard; the validator's '> N cycles without signal' check and rules-only baseline comparison expose starvation; thresholds live in config and are recalibrated on paper history, never loosened in live without the validator's promotion gate.
- Cost creep: worst case 11 calls per cycle with 5 Sonnet and 1 Opus; strong trends make every candidate look long and push G1 pass rates up. Mitigation: G1 skips debate for no-setup candidates, head/risk/derivatives are batched, head is skipped when nothing is actionable, news call skipped without new headlines, hourly re-ranking, prompt-cached static system prompts, config knobs for candidates_per_cycle and batched bull/bear (P3 style) or Haiku debate in paper mode, daily LLM spend cap that degrades to HOLD-only with a Telegram alert.
- Latency inside the 15-minute window: four sequential LLM layers (Haiku -> Sonnet debate -> Sonnet risk -> Opus). Mitigation: parallel Haiku and bull/bear, tiered timeouts (20/40/60s), one retry max, abstain values on failure, 5-minute cycle deadline -> HOLD-all; code SL/TP/time-stop never wait on an LLM; fills at next bar open consistent with delay_bars = 1.
- Herd thinking / correlated errors: all roles ultimately read the same candles and a bad feature biases everyone. Mitigation: strict partitioning at the analyst layer (technical never sees flow or news), bull and bear never see each other and use different procedures, mandatory disconfirming_evidence fields, head classifies disagreement instead of counting agreement, risk vetoes duplicated in code (G3/G4), validator IC allowlist decides which features prompts may cite, journal tags which channels agreed so 'everyone agreed and it still lost' is detectable.
- Prompt bloat, prompt-cache misses and fabricated numbers: packs across 3 timeframes plus flow, events and positions can grow. Mitigation: compact labelled JSON with rounded numbers, no raw candles beyond 20 closes, title-only headlines, <= 3 event summaries, citation discipline (every evidence item names a pack field; code rejects unknown fields), stop/TP proposals clamped and re-validated in code, per-call input token budgets asserted in mock tests.
- Over-trusting estimated or external data: liquidation clusters are projected, not observed; Fear & Greed and RSS may be stale or empty. Mitigation: data_confidence flags on the flow pack, 'empty feed is not a calm market' feed_health reporting, stale-headline flags, low-confidence flags only ever block or shrink and never approve, marked as such in Telegram and journal.
- Structured-output drift and schema failures: invalid JSON must never crash a cycle or be silently treated as bullish. Mitigation: pydantic validation on every output, abstain fallbacks the head is told about, no retry into an order, automatic fallback from batched to per-symbol calls when a batched response fails validation, mock LLM backend with schema fixtures and canned-scenario regression tests for expected verdicts of every role, prompts versioned.
- Thesis re-scoring churn: re-scoring held positions every 15 minutes can flip hold/exit on noise. Mitigation: exit on health only when <= 4 for two consecutive cycles or a red line is hit; code SL/TP remain the primary exit; cooldown after a risk exit.
- Correlation-regime and bear/risk prompt drift: FUSED/MACRO firing on thin data or the bear/risk prompts sliding toward rubber-stamping or reflexive decline. Mitigation: hysteresis dead band and config thresholds recalibrated on paper history, FUSED means de-gross not go-to-cash, transitions logged to Telegram, decline/veto rates and counterfactuals in the daily review, offline regression tests on canned scenarios.
- Behavioral severities and decay state rest on heuristics that are unreliable with few trades (< 20-30 closed). Mitigation: min-sample rule - report but do not change thresholds, floors or decay state until enough samples; journal abstains from action items until >= 20 closed trades.
- Paper results may not transfer to live because fills are simulated, and a confident but wrong Opus decision still moves real money. Mitigation: slippage model with sensitivity table, bootstrap Sharpe gate and walk-forward in the validator, testnet stage before live, explicit live confirmation, all hard limits in code, the previous session's 'NOT VALIDATED' backtest status must be improved before any live promotion.
- Telegram outage or secrets leakage: a failed message must never block trading safety, and prompts/messages must never carry keys. Mitigation: notifications queued with retry, state persisted before notification, failures logged not raised; ANTHROPIC/BINANCE/TELEGRAM env vars stripped from everything the LLM sees, tokens masked in logs, no account identifiers in Telegram.

## What was taken from each

**From P1 (capital preservation):** the gate-by-gate structure (G0-G4) with HOLD as the free default; the bear kill at G2; code-duplicated risk vetoes (correlation > 0.8, FUSED halving, CVaR-budget sizing, participation and spread limits); the funding-settlement-minute and revenge-trade blocks; the validator as a code role with the IC feature allowlist; the daily LLM spend cap; bear's strongest point and risk note in the Telegram BUY message; the over-conservatism risk and its dashboard mitigations.

**From P2 (decision quality):** the four strictly partitioned evidence channels and the rule that no analyst sees another's verdict; `washout_setup` as the one flow-driven path into the debate; tiered timeouts, abstain semantics and telling the head which channels abstained; citation discipline (code rejects unknown field names); `feed_health` / "empty feed is not a calm market"; the head's confidence cap `min(bull, risk) + 0.05` and the "4h above cloud unless washout + survivable" rule; exit-churn mitigation (health <= 4 for two consecutive cycles); the heartbeat Telegram event; secrets stripping.

**From P3 (lowest cost):** `timing` (now / wait_pullback / wait_confirmation) in the technical output; `bull_point_reliability` scoring in risk_manager; the slippage + 2x fee <= 25% of stop distance rule; automatic fallback from batched to per-symbol calls on validation failure; the config knob to batch bull/bear (or run them on Haiku in paper mode); the explicit list of what the executor enforces, folded into G4 and Step 6; the min-sample rule for bias severities.

## Constraints check

- 10 roles (7 LLM: 5 Haiku-tier call sites across 4 roles, 3 Sonnet, 1 Opus; 3 code roles: scanner, validator, and execution folded into the flow).
- User tiers preserved: cheap analysis (technical, derivatives_flow, news_sentiment, journal) -> Haiku; research/risk (bull, bear, risk_manager) -> Sonnet; head -> Opus.
- Worst case 11 calls per cycle for 2 candidates + 1 open position (<= 14); typical 7-8; halted cycles 0.
- Every trade event emits Telegram; dashboard and mock backend requirements are carried in the cycle flow and risks.
- Vibe-Trading text is rewritten in our own words; only formulas and checklists are kept with MIT attribution.

## 세 제안 요약

HOLD is the free default; an LLM is called only when a code gate says there is something worth deciding. Spot-only: every bearish signal maps to "no entry / exit", never short.

### Decision quality first: maximize diversity and independence of evidence before the head decides. Four evidence channels are kept strictly partitioned at the analyst layer: (1) price structure / technical, (2) derivatives and flow (funding, OI, long/short, estimated liquidation clusters, order-book imbalance - this is also our only "on-chain proxy", since no on-chain data is available), (3) news / event sentiment, (4) code-computed risk and regime numbers (correlation regime, VaR/CVaR, liquidity, behavioural-bias severities). Each analyst sees only its own data slice and never another analyst's verdict. Bull and bear are a synthesis layer that both read the same frozen evidence but not each other, and each must list disconfirming evidence. The head reads everything, classifies disagreement (horizon / caliber / risk preference / information) instead of counting votes, never averages confidences, and emits a falsifiable thesis. Everything that is a formula (indicators, factor ranks, funding regime labels, liquidation estimates, VaR, correlation density, slippage) is computed in Python and handed to the LLMs as compact JSON; LLMs only interpret, argue and decide. Roles that would merely restate a feature table (an LLM scanner, separate pattern-school agents) are rejected.

### Lowest cost, simplest pipeline. Everything that is arithmetic (indicators, factors, correlation, VaR, slippage, thesis-assumption checks, journal metrics) runs in code with model=none; LLM calls are reserved for interpretation and judgment. Overlapping skills are merged into one Haiku "market_analyst" (technical + derivatives + sentiment composite) instead of three roles; bull, bear, risk and head each run ONCE per cycle batched over all surviving candidates (max 3, since max 3 positions) instead of once per candidate; cheap code gates between stages skip the expensive Sonnet/Opus stages whenever nothing is actionable. The head still receives an independent bull case and bear case (parallel Sonnet calls, different prompts, same frozen evidence) and must apply the stacking rule (never average, classify the disagreement, quote the losing side).
